# LifeSkill Hub Design System

本文件约束整个产品后续页面的视觉语言。Figma 原型是设计参考，真实产品能力和数据边界仍以 `PRODUCT.md` 与 `ARCHITECTURE.md` 为准。

## 1. 设计目标

- 简约但不空洞：主要信息靠排版、间距和层级表达，不靠大量装饰。
- 高级但不晦涩：操作入口可识别，状态反馈简短，功能边界如实展示。
- 稳定而一致：同一层级的字号、图标、间距和圆角在不同页面保持一致。
- 内容优先：聊天、学习内容和可靠动态始终是视觉中心。

## 2. 基础令牌

实现令牌集中在 `frontend/src/styles.css` 的 `:root`，页面组件不得随意新增相近颜色或尺寸。

| 用途 | 约束 |
| --- | --- |
| 字体 | Plus Jakarta Sans + Noto Sans SC；代码或短标识使用 JetBrains Mono |
| 页面背景 | `#F8F9FB` |
| 正文 | `#0D1117` |
| 主色 | 钴蓝 `#2563EB`，只用于主操作、选中态和关键进度 |
| 成功/可信 | 青绿 `#16836B` |
| 正文基准 | 13–14px；辅助信息 9–11px；页面标题约 23–29px |
| 圆角 | 5px、8px、12px 三档；避免无理由的大胶囊和大圆角 |
| 桌面侧栏 | 76px，导航项 54px，主图标 20px |
| 内容宽度 | 对话正文约 700px，学习正文约 760px |

## 3. 图标规则

- 只通过 `frontend/src/components/Icon.tsx` 使用 Lucide 图标，页面不要直接导入图标库。
- 默认线宽为 1.9，主导航 20–21px，普通操作 16–18px，辅助状态 12–15px。
- 同一动作只使用一个固定图标语义，例如“对话”始终使用 MessageSquare，“学习”始终使用 BookOpen。
- 图标不能单独承担含义：不熟悉的操作需要文字、`aria-label` 或提示。
- 不使用表情符号、字符图标、混合风格的实心图标，也不为了装饰放置无功能按钮。

## 4. 页面骨架

- 一级入口固定为对话、学习、动态，不新增无产品闭环的一极页面。
- 桌面使用 76px 左侧主导航；大屏对话可展示真实会话上下文面板。
- 低于 768px 时切换到底部导航，输入区固定在内容底部，不压缩正文。
- 对话消息不使用传统大气泡；发送者、时间和内容分层展示。
- 卡片只承载结构化信息或可操作内容，普通文字不额外套卡片。

## 5. Agent 状态的视觉边界

- 只展示已经发生、可以核验的事件，例如工具名、来源、状态和耗时。
- 不展示模型原始思维链，不用动画伪装“正在推理”。
- 长期 Skill 先展示结构化草案，并明确“尚未创建”；用户确认后才改变状态。
- 模型、搜索或来源能力尚未接入时，显示简洁边界说明，不生成假数据填满界面。

## 6. 新页面检查清单

1. 是否复用了现有颜色、字号、间距与圆角令牌？
2. 是否所有图标都经过统一 `Icon` 组件，尺寸和语义一致？
3. 桌面与手机是否都保持主要操作可见且内容不溢出？
4. 页面上的每个按钮是否真实可用？暂未实现的能力是否被如实说明？
5. Agent 信息是否可验证，是否避免了假状态和原始思维链？

## 7. 开发后讲解去重

每次开发后的新手讲解遵循 `ENGINEERING_STANDARDS.md` 的“每次开发后的成长交付”。只深入讲一个与本次改动最相关、之前未讲透的知识点；已稳定的产品和 Agent 边界只简短回顾并引用对应文档，避免每次重复同一套术语。
