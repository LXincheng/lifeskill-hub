# 产品说明

## 1. 产品目标

让个人用户通过自然语言，把兴趣和目标转化为可持续执行、可核验、可学习的数字能力，而不是增加一个传统任务管理器或新闻聚合器。

## 2. 一级功能

以下描述包含产品目标。当前是否可用必须以 `PROJECT_CONTEXT.md` 的“当前真实能力边界”和 `DEVELOPMENT_PLAN.md` 的勾选状态为准。

### 2.1 对话

默认首页。当前支持普通问答、创建并确认周期 Skill；搜索、执行计划、运行 Skill 和从对话生成学习内容按开发计划逐步接入。

系统识别到重复执行或持续关注意图时，应展示可编辑的 SkillDraft。用户确认后才允许创建 Skill；调度和通知必须在各自里程碑完成后才能启用。

搜索或多角色协作时，在对话内展示操作事件：规划、搜索、核对、整理、落库。默认折叠，不展示模型思维链。

### 2.2 学习

学习内容按文件夹组织。一个文件夹可以包含：

- 学习卡片
- 长文阅读
- 测验
- 代码练习或行动 Checklist
- 外部链接、图片和可信视频

当前内容由用户手动整理；从计划、动态或聊天自动沉淀属于 M2/M3 目标，生成时必须保留来源关系。

### 2.3 动态

动态由 Skill、学习计划和用户兴趣产生，以克制的卡片/列表展示。顶部 Tab 是用户标签的投影，不是写死频道。

目标动态卡片至少显示来源 Skill、时间、摘要、来源数量、核验状态和推荐原因。M2 先实现询问、查看证据和生成学习内容；稍后阅读、降低推送和外部通知后续接入。

## 3. 核心对象

对象名称是统一业务语言，不代表对应功能都已经实现。

- Plan：有目标和阶段的行动计划。
- Skill：可复用、可配置、可运行的能力配方。
- Watch：Skill 的一种，负责定时或事件驱动的持续关注。
- AgentRun：一次受控执行。
- Evidence：不可变的来源事实。
- Claim：由 Evidence 支撑的结论。
- LearningFolder：学习主题文件夹。
- ContentItem：卡片、文章、测验、实践等统一内容对象。
- Notification：通过应用内、Web Push 或外部渠道投递的通知。

## 4. 可信体验

- 原始来源、发布时间和采集时间必须保留。
- 行情和数字由代码重新计算；模型只负责解释。
- 重要 Claim 至少一条一手来源；高风险主题可要求两个独立来源。
- 证据冲突必须呈现，不得强行合并为确定结论。
- 低置信内容不主动推送，或明确标为“部分确认”。
- 用户可以报告无关、重复或事实错误，供后续复盘。

## 5. 非目标

MVP 明确不做：

- 真实 3D 地球或复杂地图
- 固定新闻、金融、GitHub 频道
- 独立 Agent 运行记录中心
- 展示模型原始思维链
- 社区、评论、关注他人
- Skill 商店和第三方任意代码执行
- Notion 式自由知识库编辑器
- 自动投资建议或医疗诊断
- 无法暂停的长期自治 Agent
- 为视觉效果堆积指标和仪表盘

## 6. 长期扩展边界

- 编程学习、官方资讯研究和长期关注是首批可上线能力。
- 行情能力必须使用可追溯的实时数据源；模型只能解释，不能编造价格、涨跌或时间。
- 购票能力先做查询、比选和候选方案；涉及登录、锁座、下单、支付时必须使用明确 Tool，并在最终外部写操作前由用户确认。
- “多 Agent”优先表示同一 Harness 中职责隔离的 Planner、Researcher、Verifier、Composer 步骤，不等于部署多个自治服务。

## 7. MVP 成功标准

- 用户能从一段聊天创建并确认一个 Watch Skill。
- Skill 能调用至少一个真实来源适配器并保存 Evidence。
- 生成内容中的 Claim 能追溯到 Evidence。
- 动态卡片能进入一个学习文件夹并生成至少三种内容类型。
- 用户能暂停 Skill、修改频率并查看最近一次执行结果。
