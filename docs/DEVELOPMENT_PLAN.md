# 开发计划

## 原则

- 每个里程碑交付可运行、可演示的纵向切片。
- 优先完成真实闭环，不批量创建空页面和抽象框架。
- 多 Agent 先实现为可观测状态机步骤，不引入独立框架。
- 每次扩展来源前，先补齐 Evidence、Claim 和核验测试。

## M0：仓库与运行骨架（已完成）

- [x] 产品、架构与接续文档
- [x] React + TypeScript 前端目录
- [x] Spring Boot + Spring AI 后端目录
- [x] PostgreSQL 本地配置
- [x] 前后端构建通过
- [x] 命名、架构与开发交付规范
- [x] GitHub 公开仓库和首次推送

验收：新机器按 README 能启动数据库、后端和前端；`/api/status` 返回状态。

## M2：第一个可靠来源与动态

- GitHub/官方文档 Source Adapter
- Evidence 规范化、去重和持久化
- Claim 与 Evidence 绑定
- Verifier 和确定性 Policy Gate
- `Java Agent Weekly` 定时运行
- 动态页 Tab、列表和详情

验收：一条动态可追溯原始来源；无 Evidence 的 Claim 被测试拦截。

## M3：从动态进入学习

- [x] 学习文件夹与手动文档 CRUD
- [x] 学习路径、文章、笔记、测验与清单 ContentItem 类型
- [x] 学习路径时间线、文章代码块和交互测验视图
- 学习卡片 ContentItem 与复习交互
- 动态生成学习单元
- 学习进度和测验记录
- 复习任务

验收：从动态点击学习后生成文件夹内容，完成状态可持久化。

## M4：通知与复盘

- 应用内通知
- Web Push；微信/外部渠道只做适配器接口
- 免打扰、长度、频率和渠道设置
- 打开、收藏、无关、事实错误反馈
- Skill 周度效果复盘和调整建议

验收：用户可控制何时收到什么内容，并能暂停全部主动推送。
